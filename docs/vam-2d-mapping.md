# 2D-сцены «как в приложении Vam Balkon»

Дата: 2026-09-19. Конфигуратор сайта — **только 2D**, как в приложении-образце:
живой 3D (THREE.js, PBR-текстуры), расчёт цен и админка материалов/цен удалены
по решению владельца.

Код: `src/pages/Configurator/` — `vamCatalog.ts` (модель выбора, проверка, сводка для заявки),
`vamApp.generated.ts` (**генерируется** `scripts/importVamApp.mjs`), `VamScene.tsx` (режим «как в приложении»),
`PlanScene.tsx` + `render/` (режим «по чертежу»), `FinishStep.tsx`, `SetupStep.tsx`, `useConfigurator.ts`.
Ассеты: `public/vam/` (≈25 МБ, ≈2300 файлов; слои — `public/vam/x/`). Импорт актуальной версии:
`node scripts/importVamApp.mjs` (см. раздел «Логика приложения»). `importVamAssets.mjs` — только
витрина (`showcase`) и плашки (`swatch`). Скрипты и результат коммитятся (в рантайме `D:\` не читается).

> Разделы до «Логика приложения» описывают первую версию (ручное сопоставление, `vamManifest.ts`,
> `LeftPanel`/`RightPanel`); они сохранены как расшифровка имён файлов, архитектура — в последних разделах.

## Как устроен оригинал (расшифровано из `libapp.so` + просмотра картинок)

Каждая картинка — слой **800×800 (иногда 1200×1200)**, уже стоящий на своём месте
внутри холста. Сцена = слои, наложенные друг на друга в точку (0,0), никакой
геометрии и подгонки координат не нужно. Порядок: пол → стены/потолок/окна →
плинтус → шкаф → стул → светильник.

`construktor/stenaN/cvetM_K.webp`:

| Часть имени | Значение |
|---|---|
| `N` | номер куска комнаты. 5, 8 — **пол**; 1,2,3,4,6,7,9,10 — стены, потолок (3, 9), окна (2, 10), подоконник/парапет (7), угловой клин (4) |
| `M` (`cvetM`) | **планировка балкона** (не цвет!). M1 — угловой (Г-образный), M4 — длинная лоджия, M6 — квадратный. M2, M3, M5 — неполные наборы (пол + торцевая стена) под фоны `imgN_K` — не используются |
| `K` | **цвет/декор** (0..18 у вагонки и паркета, 0..10 у ламината, 0..5 у МДФ). `K` согласован между кусками: тот же `K` красит стены, откосы и окна |
| папка | семейство материала стен: `stenaN/` — ламинат, `vagonka/4m/stenaN/`, `sten_parket/4m/stenaN/` (паркет), `mdf/stenaN/` |

Исключения нумерации: у вагонки окна/потолок квадратного балкона названы `M5`
вместо `M6` (торцевая стена — `M6`). У паркета нет кусков 4 и 9 (угловой клин,
второй потолок) — берутся из вагонки того же `K`. МДФ есть только для углового.

Дополнительные слои (общие для всех планировок — «слоты» в одном пространстве
камеры, поэтому ложатся на любую сцену):

| Слой | Файлы | Что это |
|---|---|---|
| Плинтус | `plintus<M>_K` (K=1..3) — только основная серия, «двойники» `plintus<M>1` рисуют смещённый контур | цвет плинтуса; серия зависит от планировки |
| Светильник | `lamp1_K`, `lamp11_K`, `lamp2_K`, `lamp21_K` (K=1..6; `lamp2*` на холстах 1200) | 6 моделей (иконки `icon/lampK.webp`: подвесной, плоский, накладной цилиндр, лофт-клетка, трековый чёрный/белый) в 4 расположениях: `lamp1` — ближний + дальний, `lamp11` — зеркально, `lamp2`/`lamp21` — одиночный дальний |
| Барный стул | `chair/chair1_1_K`, `chair2_1_K` (K=1..10) | 2 положения (ближе/дальше), 10 цветов |
| Шкафы | `shkaf/shkafD_K` (вдали), `shkafD_1_K` (слева), `shkafD_2_K` (справа), D=0..3 | D: 0 низкий с подушками, 1/2/3 — 2/3/4 дверцы; K=1..19 (у 4-дверного слева — 15). Это вариант «Жалюзи» |
| Шкафы, ещё глубины | `shkafDD_K`, `shkafDDD_K`, `shkafDDDD_K` (цифра модели повторена 2–4 раза) | тот же шкаф дальше по длинной лоджии: «В глубине», «Ближе к концу», «В самом конце» (только жалюзи, K=1..15) |
| Шкафы ЛДСП | `shkaf/shkaf_ldspD_K`, `_1_K`, `_2_K` | то же в материале «ЛДСП» (гладкие дверцы), K=1..12; иконки `icon/material_ldsp.webp` / `material_jaluzi.webp` — «Материал шкафа» |
| Сушилки | `dryer/chair1_1_K`, `dryer/chair2_1_K` (файлы сохранили имя «chair»), K=1..8 | в приложении сушилки нумерованы 1..8 (иконки `icon/numberK.webp`, K = номер). Пары `K` и `K+2` — один тип в двух цветах (1/3 и 2/4 — настенные гармошки, 5/7 и 6/8 — потолочные). `chair2_1` — зеркальное расположение; в нём кадры 5 и 7 пустые (6 моделей вместо 8) |
| Цветы | `flowers/chair1_1_K` (кашпо на правом окне), `chair2_1_K` (горшок на левом парапете), K=1..3 | 3 растения (иконки `icon/flowers_cvetK.webp`: подвесное, трава, зелень) |
| Плиточный пол | `stena5/plitka_cvetM_K`, `stena8/plitka_cvetM_K` (K=0..2) | второе семейство пола: беж / терракота / синий. Нумерация `M` у плитки **своя**: подобрана по совпадению силуэта с полом планировки (99–100%): угловой → `M3`, длинная → `M1`, квадратный → `M5` |

**Плашки цвета — настоящие картинки приложения.** `assets/images/cvetK.jpg`
(K=0..10) — фотографии ламината; `K` совпадает с `_K` у ламината и на **полу**, и на
**стенах** (проверено по цветности слоёв). Они же используются как круглые
плашки. Плитка — `plitka_cvetK.webp`, стулья — `icon/chair_cvetK.webp`, растения —
`icon/flowers_cvetK.webp`. У плинтуса иконки `plintus1..3` — белый / серый /
тёмно-коричневый (подписи в подсказках). Названий цветов вагонки/паркета/МДФ в
APK нет — плашка окрашена усреднённым цветом слоя.

Спрайты на холсте 1200×1200 = центральный кусок 800×800 (200 px поля со всех
сторон) — импорт обрезает.

Пережатие: исходные webp почти без потерь (≈83 МБ на нужное подмножество); при
импорте кодируем в webp q82 / alpha q90 → ≈12 МБ.

## Что подключено в сайте

- **Остекление** (левая панель, только у планировок, где есть варианты):
  «Стандартное» — собственные окна набора (с занавесками); варианты
  подменяют куски-окна (2 и 10) фоном `imgN` из APK: угловой — «Окна от
  парапета» (`img4_0`), «Панорамное» (`img5_0`); длинная — «Окна от парапета»
  (`img8_0`), «Панорамное» (`img9_0`), «Окна в стене» (`img8_1`). Для варианта
  появляются вкладки «Рамы» (цвет оконных рам, `rama<N>_K`, K=0 — белый без
  слоя) и, где есть, «Подоконник» (`podokonnik<N>_K`). Вариант отражается на
  заявку. Порядок слоёв: фон → пол → стены → рамы →
  подоконник → плинтус → мебель → свет.
- Левая панель (2D): выбор планировки с превью. Правая: «Материалы» (стены →
  семейство + цвет; пол → ламинат/плитка + цвет; плинтус), «Мебель» (шкаф:
  тип/материал жалюзи·ЛДСП/положение/цвет; барный стул; сушилка №1..8 в двух расположениях; цветы:
  кашпо на окне или горшок, 3 растения), «Свет» (6 моделей × 4 расположения).
- Состояние: `state.vam` (`VamSelection`), нормализуется по манифесту
  (`normalizeVamSelection`) при загрузке из `localStorage`.
- Цен нет. Заявка на замер уходит с описанием конфигурации: `metadata.summary` (строки
  «Планировка / Стены / Пол…» из `vamSummary`), `metadata.scene2d` (сам выбор) и
  PNG сцены; `balconySize` необязателен. Админка заказов показывает те же строки.
- «Скачать» — `VamScene.captureImage()` (canvas по слоям), PNG 800×800.
- Витрина для маркетинговых страниц: `public/vam/showcase/{hero,promo,story}.webp`
  (тот же скрипт склеивает их из слоёв; набор в `SHOWCASE` в `importVamAssets.mjs`).
  Используются на главной (hero, промо) и в «О компании» вместо прежнего
  SVG-арта — компонент `BalconyArt` удалён. Легаси-страницы в `public/*.html`
  (`hero-balcony-render.jpg`, `hero-slider/*.svg`) не тронуты.

## Известные ограничения / что не сделано

- Не подключены:
  - рамы и подоконники для «Стандартного» остекления: `ramaN_K` /
    `podokonnikN_K` нарисованы под фоны `imgN_K` и на собственные окна
    планировок не ложатся — доступны только внутри вариантов остекления;
  - плоские цвета потолка (`stena4/potolokC_K`, `stena9/potolokC_K`, C=1..3
    форма потолка, K=0..3 цвет): C1 похож на угловой, C3 на квадратный, но
    точного совпадения силуэтов нет — не подключено;
  - Сушилки и цветы стоят в общем «пространстве камеры»: одинаково на всех
    планировках, но на квадратной настенная сушилка №1 «висит» над полом
    (в приложении та же картина — спрайты общие).
- Названий цветов в APK нет — на плашках только усреднённый цвет (`hex` в
  манифесте), подписи «Цвет N».
- **Остекление (фоны `imgN`) — подключено частично** (см. «Что подключено»):
  выбор вариантов для углового и длинного; квадратный без вариантов (фон 10 не
  даёт ничего нового). Остальные фоны остаются не подключёнными — расшифровка:
- **Ещё до девяти планировок на «голых» фонах — расшифровано.**
  `assets/images/imgN_K.webp` (N=2..10, 22, 33, все 800×800) — рендер
  неотделанного балкона: серые стены, окна, вид на город. На фон накладываются:
  `rama<N>_K` — цвет оконных рам, `podokonnik<N>_K` — цвет подоконника (**серия
  `N` = фон `imgN`**, проверено наложением: ложатся точно), плюс отделочные
  куски `stena*` и слои плинтус/свет/мебель. Соответствие фон ↔ набор кусков по
  корреляции контуров: фоны 8, 9 → набор `M4` (длинная), 10 → `M6`
  (квадратный), 3, 6, 7, 22, 33 (+2, 4, 5) → `M1` (угловой); `M2/M3/M5` — куски
  пола и торцевой стены под эти фоны. Разные фоны одной геометрии — это
  **варианты остекления** (панорамное, тёмные рамы, глухая стена с окнами).
  Подключены только те фоны, где справа получается цельная картина (парапет
  или остекление в пол, окна в стене); фоны 3, 22, 33, 3_7 дают пустую правую
  часть, 6 и 7 повторяют собственные окна углового набора, 10 для квадратного
  ничего не добавляет.
- Секреты в `APK/assets/flutter_assets/dotenv.env` (боевые ключи чужого бэкенда)
  не используются и в репозиторий не попадали.


## Логика приложения — расшифровка кода (2026-09-20)

Раньше пары «фон + набор» подбирались на глаз. Теперь логика взята из самого приложения:
`libapp.so` (Dart AOT) дизассемблирован **blutter** (Docker, образ строится из
`github.com/worawit/blutter`; вход — `APK/lib/arm64-v8a`, выход — `asm/`, `pp.txt`).
Результат — `scripts/vam-app-spec.json` (экраны → виды → хотспоты → попапы → префиксы слоёв;
получен скриптом разбора `asm/vambaalkon2/screen/screen_N.dart` и `widget/Widget_stena*.dart`).

- Экран 1 (`screen_1`): тип балкона (Г-образный, П-образный, Лоджия до 5м, Лоджия до 8м,
  П-44Т «Утюг») → остекление («с парапетом» / «до пола»; у П-44Т — «Левосторонний» /
  «Правосторонний»). `_onNextPressed` выбирает экран: Г 2/3, П 4/5, Л5 6/7, Л8 8/9,
  П-44Т 10/11. Экран 11 — экран 10, отражённый (`Transform` + `Matrix4`).
- Экраны 2–11 («Выбор отделки») — два вида, у каждого голые фоны (`img*`) и хотспоты
  `MyInkWell<id>` (`widget/Widget_stena<id>.dart`). Хотспот открывает попапы материалов:
  `vert_laminat` / `vert_vagonka` / `strn_parket` / `mdf` (стены, потолок, пол),
  `laminat_podokonnik` (рамы `rama*`, подоконники, плинтус, свет `lamp*`), `shkaf*` (шкафы),
  «декор» (стул, сушилка, цветы). Каждая поверхность красится **отдельно**; пока выбор не
  сделан, рисуется голый фон.
- Виды: 2/6 — `img2_0`; 3/7 — `img22_0`+`img2_7`; 4 — `img4_0`; 5 — `img5_0`; 6 — `img6_0`;
  7 — `img7_0`; 8 — `img8_0` | `img8_1`; 9 — `img9_0` | `img9_1`; 10/11 — `img10_0` | `img10_1`;
  второй вид 2/4 — `img3_0`+`img3_6`, 3/5 — `img33_0`+`img3_7`.

**Какой кусок на каком виде.** Поверхности комнаты в приложении пронумерованы 1–10: куски
1–5 нарисованы под **первый** вид экрана, 6–10 — под **второй**. Стена 2 = куски 2 (вид 1) и
7 (вид 2), стена 3 = 3 и 10, потолок = 4 и 9, пол = 5 и 8, торцевые стены = 1 и 6. Выбор
цвета на одном виде красит и парный кусок на другом (`layers[].v` в манифесте). Рамы,
подоконники и плинтус — пары «`X` / `X1`»: вид определяется по совпадению контура (импортёр),
плинтус — по краю пола, мебель и свет остаются на своём виде. Проверка целостности:
`node scripts/verifyVamApp.mjs` (все 4879 файлов на месте, контуры материалов совпадают).

Сайт: `scripts/importVamApp.mjs` (читает spec + `D:\VamBalkon_extract`, пишет `public/vam/x/` и
`src/pages/Configurator/vamApp.generated.ts`), рантайм — `vamCatalog.ts` (выбор = `picks`),
`SetupStep.tsx`, `FinishStep.tsx`. Старый `importVamAssets.mjs` теперь нужен только для
`public/vam/showcase` и `swatch` (папку `x/` не трогает).


## Вид «по чертежу» (актуально на 2026-10-01)

Готовые сцены приложения — всего 5 фиксированных балконов, они не повторяют скос и уступы
чертежей. Поэтому второй режим строит комнату из размеров чертежа.

- `planShapes.ts` — планы шести форм (контур в мм, вид каждого ребра: дом / стена / панель /
  остекление / бетон, высоты, проём двери и окон, размерные линии). Чертежи не в масштабе:
  контуры — подгонка по подписям методом наименьших квадратов с сохранением топологии
  (Сапожок 4,18 м², Лодочка 2,68 м² — как в паспортах П-44Т). Размеры прямых балконов
  (Обычная/Удлинённая лоджия, Хрущёвка) — типовые, не с чертежа.
- `ShapePlan.tsx` — карточка чертежа в стиле исходных чертежей.
- `render/` — собственный пиксельный рендерер без 3D-движка (Web Worker, запасной вариант на
  главном потоке): `scene.ts` строит плоские грани комнаты, `lighting.ts` запекает дневной свет
  (форм-фактор окон + затемнение углов), `raster.ts` растеризует по пикселям с z-буфером,
  mip-текстурами и 2x сглаживанием, `lamps.ts` — 6 светильников приложения, `hotspots.ts` —
  точки нажатия из буфера идентификаторов. `usePlanViews.ts` — одиночный цикл рендера.
- Текстуры: `node scripts/importVamTextures.mjs` → `public/vam/tex/` (вырезаны из торцевых
  стен готовых сцен), улица за окнами: `node scripts/importVamStreet.mjs` → `tex/street-pano.webp`.
- Переключатель «По чертежу / Как в приложении» — в шапке экрана отделки; по умолчанию
  «как в приложении» (`normalizeVamSelection`).

Цель текущей работы (ветка `feat/unified-visualizer`): слить два режима в один — геометрия из
чертежей, весь внешний вид (материалы, рамы, подоконники, ручки, стекло, свет) из ресурсов APK.
