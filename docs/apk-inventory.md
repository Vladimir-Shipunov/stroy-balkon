# Опись визуальных ресурсов APK Vam Balkon (этап 2, 2026-10-01)

Источник: `D:\VamBalkon_extract\APK\assets\flutter_assets\assets\images\` (папка `construktor/`
продублирована в корне распаковки). Всего ≈2460 растровых файлов: 2417 webp, 12 jpg, 2 png; плюс
ресурсы Android (`res/drawable-*`, иконки лаунчера — не нужны) и шрифты. Векторной графики,
3D-моделей и спрайт-атласов нет. `shaders/ink_sparkle.frag` — эффект нажатия Flutter, к визуалу
балкона не относится.

## Главный вывод

**Все визуалы балкона в APK — готовые перспективные CGI-картинки, привязанные к одной камере.**
Отдельных картинок анфас (профиль рамы, окно, дверь, ручка, козырёк, отлив) в приложении нет:
окна, двери, ручки, откосы, шторы, отливы нарисованы прямо внутри «голых» фонов `imgN_K`, а слои
`ramaN_K` и `podokonnikN_K` — это вырезанные из тех же рендеров пиксели рам и подоконников,
перекрашенные в 6 цветов. Двери, козырька, отлива, москитной сетки как выбираемых элементов в
приложении **нет** (в строках `libapp.so` нет слов «козырёк», «отлив», «ручка», «подоконник»;
профили «Rehau/Veka…» и «ПВХ 60/70» — только текст калькулятора).

Следствие: готовую картинку APK нельзя «приложить» к произвольной геометрии чертежа. Её можно
(а) показывать как есть там, где геометрия совпадает с одной из 5 сцен приложения, (б) использовать
как источник внешнего вида — вырезать плоские текстуры и выпрямлять (гомография) почти фронтальные
участки с окнами, чтобы получать из них материал для граней рендерера по чертежу.

## Что из этого уже в репозитории

- `public/vam/x/` — всё, что использует логика приложения (2198 файлов: фоны `bg/`, слои, иконки
  `ui/`); верифицируется `scripts/verifyVamApp.mjs`. Не импортированы по замыслу: неиспользуемые
  в потоке приложения куски `stena1` (отдельные цвета), `laminat_podokonnik2` (8), `lodjia.webp`.
- `public/vam/tex/` — плоские текстуры ламината/вагонки/паркета/МДФ/плитки (вырезаны из торцевых
  стен) и панорама улицы `street-pano.webp`.
- `public/vam/swatch/`, `public/vam/extras/`, `public/vam/showcase/` — плашки, светильники для
  рендерера, витрина сайта.

Единая структура ресурсов уже есть, повторное копирование не нужно: `x/` — слои сцен приложения,
`tex/` — материалы для рендерера по чертежу, `swatch/` — цвета.

## Чего в APK нет (и это нельзя «найти ещё раз»)

Дверь как отдельный элемент, козырёк, отлив (кроме как пиксели внутри рендеров), ручка отдельно,
профили/сечения рам, откосы как выбор, разные типы окон (одностворчатое/двустворчатое…), цвет
стекла, москитка, тонировка. Всё это придётся брать из самих рендеров (вырезка/выпрямление) или
рисовать в стиле рендеров — на этапе 3 решаем по каждому элементу.

## Кандидаты для вырезки из рендеров (проверить на этапе 3)

- Окна анфас: левая часть `img10_0` (балконный блок с дверью и шторами, угол ≈ 20° к камере),
  `img3_7` (панели с видом на улицу — уже использованы для панорамы), `img6_0` (три створки с
  ручками, сильная перспектива). После гомографии получаем рамку, импост, ручку, стекло, шторы.
- Подоконник с отливом: правая часть `img10_0`, `img6_0`.
- Ограничения: разрешение окна в кадре ≈ 250–400 px, шторы и стекло с бликами и отражением города.
